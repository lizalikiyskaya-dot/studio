# Почта платформы

Платформа отправляет письма в четырёх случаях:

| Событие | Кому | Файл |
|---|---|---|
| Ученик поработал в своём кабинете | наставнику | `lib/notify.ts` → `notifyMentorOfStudentEdit` |
| Наставник внёс правки в кабинет ученика | ученику | `lib/notify.ts` → `notifyStudentOfMentorEdit`. Сейчас не уходит, пока в окружении нет `STUDENT_EDIT_EMAILS=on`. Маячки в кабинете остаются. |
| Регистрация | ученику («заявка на рассмотрении») и наставнику («новая заявка») | `lib/notify.ts` → `notifyRegistration` |
| Одобрение заявки / возврат доступа | ученику | `lib/notify.ts` → `notifyApproved` |
| Запрос «Забыли пароль?» | тому, кто запросил | `lib/notify.ts` → `sendPasswordResetEmail` |
| Утро дня оплаты (Москва, 09:00–11:59) | тому, у кого наставник указал день оплаты и не выключил письмо | `lib/paymentReminderScheduler.ts` |
| Наставник открыл методичку | ученику, если у методички включено письмо | `lib/notify.ts` → `notifyStudentGuideOpened` |

## Переменные окружения

Прописываются в `/srv/studio/app/.env` (600, владелец `studio`). В репозитории
их нет и быть не должно.

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=lizalikiyskaya@gmail.com
SMTP_PASSWORD=<пароль приложения Google, 16 символов, без пробелов>
MAIL_FROM="Студия художественной прозы <lizalikiyskaya@gmail.com>"
APP_URL=https://studio.lizalikiyskaya.ru
```

Если `MAIL_FROM` не задан, имя остаётся «Студия художественной прозы»,
адрес — `SMTP_USER`. Так и должно быть, пока ящика `lizaandreenko` нет.

Когда ящик заведут, в том же `.env` нужно три вещи (пароль в репозиторий не класть):

1. Создать почтовый ящик с локальной частью `lizaandreenko` (домен — тот, где будет ящик).
2. Прописать его в SMTP: `SMTP_USER` и `SMTP_PASSWORD` этого ящика. Иначе сервер
   откажет чужому адресу в поле From.
3. Задать отправителя целиком:

```
MAIL_FROM="Андреенко · студия художественной прозы <lizaandreenko@ДОМЕН>"
```

`MAIL_FROM` перекрывает имя и адрес. По отдельности можно задать
`MAIL_FROM_NAME` и `MAIL_FROM_ADDRESS`, если полной строки нет.

Письма — HTML в палитре кабинета (`#F6F1E8`, `#202020`, `#FFD43B`) и текстовая копия.
В шапке жёлтая полоса и «Андреенко · студия художественной прозы». Ширина карточки до 600px, стили только инлайн. Письма ученику — от первого
лица и подписаны «Лиза Андреенко».

Три письма рисуются функциями ниже. Сами по себе никуда не уходят. Из журнала `/mentor/mail` наставник может отправить их сам: кнопка «Написать письмо», выбор учеников, правка темы и текста, превью, затем вопрос «Отправить N ученикам?». Пачка идёт по одному письму с паузой 400 мс, не больше 40 за раз. Каждая попытка пишется в `EmailLog`.

- `platformUpdateLetter({ name })` — отчёт ученику о том, что уже есть в кабинете, включая «Еженедельное задание» и «Цитату дня».
- `weeklyTaskLetter` — задание недели: название, текст, объём, срок (день до `nextPublishedOn`), кнопка на `/dashboard/weekly`.
- `dailyQuoteLetter` — цитата, автор, источник, короткая строка, кнопка в кабинет.

Образцы для превью шаблонов: `designerLetterPreviews()`.

## От кого уходит письмо

Вход в SMTP по-прежнему только из окружения: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`. Пароль в базу не пишется.

Имя, адрес «От» и Reply-To наставник задаёт в профиле. Это три пустых столбца `User` (`docs/sql/2026-10-20-mail-from.sql`, только `ADD COLUMN`). Пустое поле оставляет значение из `MAIL_FROM` / `SMTP_USER`.

Gmail (`smtp.gmail.com`) примет чужой адрес «От», только если этот ящик добавлен и подтверждён в Gmail: Настройки → Аккаунты → «Отправлять почту как». Иначе сервер отклонит письмо. Для своего домена нужны SPF и DKIM так, как просит Gmail или другой провайдер. Приложение само домен не проверяет и тестовое письмо для проверки не шлёт. Форма показывает предупреждение. Reply-To можно поставить любой, на вход в SMTP он не влияет.

Если переменные SMTP не заданы, письма не отправляются, но регистрация и
сохранение текста из-за этого не падают. Каждая попытка — и удачная, и нет —
пишется в таблицу `EmailLog` (файл `docs/sql/2026-10-19-email-log.sql`, только
новые таблица и столбец `html`). Список в кабинете наставника, раздел «Письма»:
дата, ученик, тип, тема, статус и превью письма. Можно отфильтровать по типу
и по ученику.

Пароль приложения создаётся при включённой двухфакторке:
myaccount.google.com → Безопасность → Пароли приложений. Тот же пароль
используется лендингом `lizalikiyskaya.ru` (там он лежит в `/etc/msmtprc`).

## Как часто приходят письма об изменениях

Не чаще одного раза в час на человека: первая правка после «тишины» даёт
письмо сразу, остальные правки этого часа копятся молча. Час считается по
полям `User.mentorNotifiedAt` / `User.studentNotifiedAt`, окно занимается
атомарно — параллельные правки не дадут двух писем.

Каждый может выключить эти письма себе сам: Профиль → «Уведомления на почту»
(поле `User.emailNotifications`). Письма про регистрацию, доступ и смену
пароля этим переключателем не отключаются — они транзакционные.

Письмо в день оплаты уходит само, из процесса приложения, по Москве с 09:00
до 12:00. Получатель — только тот, у кого наставник указал день месяца
(`paymentDay`). Сумма (`paymentAmount`) необязательна. Тумблер «письмо»
(`paymentReminders`) выключает напоминание для одного человека. Свой тумблер
«Уведомления на почту» тоже останавливает это письмо. Повтор в тот же день
не уходит: строка в `PaymentReminderLog`. Пока приложение запущено не в
production или стоит `PAYMENT_REMINDER_DRY_RUN=1`, SMTP не вызывается.
`PAYMENT_REMINDERS=0` выключает планировщик целиком.

## Восстановление пароля

`/forgot-password` → письмо со ссылкой `/reset-password?token=…`.
В базе (`PasswordResetToken`) лежит только SHA-256 от токена, ссылка живёт
час и срабатывает один раз, повторное письмо — не чаще раза в 2 минуты.
Ответ формы не зависит от того, есть такая почта на платформе или нет.

## Проверка после деплоя

```bash
# из каталога приложения на сервере, под пользователем studio
node -e '
const nodemailer = require("nodemailer");
require("dotenv").config({ path: "/srv/studio/app/.env" });
nodemailer.createTransport({
  host: process.env.SMTP_HOST, port: +process.env.SMTP_PORT, secure: false,
  auth: { user: process.env.SMTP_USER, pass: process.env.SMTP_PASSWORD },
}).verify().then(() => console.log("SMTP ok")).catch(e => console.error(e));
'
```
